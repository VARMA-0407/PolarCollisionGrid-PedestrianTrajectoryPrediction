Notebook: [`notebooks/PIE_Full_Pedestrian_Safety_Pipeline_Colab.ipynb`](../../notebooks/PIE_Full_Pedestrian_Safety_Pipeline_Colab.ipynb)
(generated by [`scripts/build_colab_full_pipeline_notebook.py`](../../scripts/build_colab_full_pipeline_notebook.py); edit the builder, not the `.ipynb`, then re-run it).

> **Status:** the notebook is structurally validated and its orchestration was smoke-tested locally on synthetic data in precomputed-artifact mode.
> It has **not** been run on Google Colab, on a GPU, or on the real PIE videos. The first real run is yours; every number comes from that run.

## 1. What the notebook does

It runs the implemented pipeline on every PIE video you downloaded:

PIE videos → YOLO11 + ByteTrack (Phase 3) → image-space kinematics and interaction graphs (Phase 4) → windows, multi-video training of the
GATv2 + causal TCN + multimodal decoder, evaluation (Phase 5) → conflict representation (Phase 6) → risk assessment (Phase 7) → early-warning
events (Phase 8) → Phase 9 gates, experiment report and final validation.

The notebook only *orchestrates*: the code lives in the repository (`pedsafety/multivideo/` wraps the existing Phase 3–9 public APIs).
It does **not** produce metric distances, TTC/PET, calibrated probabilities, validated warning lead times or real-time claims — see section 10.

## 5. Configure

Edit only the **central configuration cell** (all paths and switches are there). The most important settings:

| Setting | Meaning |
|---|---|
| `DRIVE_ROOT`, `PIE_RAW_DIR` | project and data folders on Drive |
| `SPLIT_SCHEME` | `PIE_OFFICIAL` (train set01/02/04, validation set05/06, test set03 as published, no calibration partition) or `PIE_OFFICIAL_CALIBRATION_FROM_VAL` (documented deviation: a whole validation set becomes the calibration partition) |
| `EXPERIMENT_ID` | empty = new experiment; the printed id = resume |
| `RUN_*` switches | a disabled stage only **verifies** existing outputs of this experiment (completion markers + hashes); it never recomputes and never borrows another experiment's outputs |
| `PERCEPTION_MODE` | `raw_video` (YOLO + ByteTrack on the MP4s) or `precomputed` (existing Phase 3 folders; recorded as `PRECOMPUTED_PHASE3_ARTIFACTS`, never as raw-video execution) |
| `PHASE3_REUSE_EXPERIMENT_IDS` | reuse Phase 3 outputs of an earlier experiment with identical perception configuration and weights, after SHA-256 verification |
| `VIDEO_SUBSET`, `PERCEPTION_MAX_FRAMES` | for a quick pilot run in a separate experiment (partial videos are labelled) |
| `TRAIN_EPOCHS`, `TRAIN_BATCH_SIZE`, `TRAIN_LEARNING_RATE` | repository defaults (20 / 64 / 0.003); changing them defines a different experiment |
| `CHECKPOINT_EVERY_EPOCHS` | 1 = lose at most one epoch after a disconnect |
| `RUN_PHASE9_PILOT_REGRESSION` | off by default. Re-runs the original single-video Phase 9 runner on `set01/video_0004`; needs `PILOT_PHASE3_DIR` **and** the pilot reference artifacts that are git-ignored (a plain clone does not contain them), so it normally only works on the machine that holds them |
| `REQUIRE_ALL_VIDEOS` | a stage counts as complete only if every video succeeded (set False to continue with the successful videos; recorded) |

Settings that change scientific outputs are frozen in `experiment_lock.json`; resuming with a different value is refused.

## 6. Select a GPU runtime

Runtime → Change runtime type → Hardware accelerator **GPU** (T4 or better) → Save. Section 1.2 prints GPU name, CUDA, GPU memory, RAM and free disk,
and stops if no GPU is attached (`REQUIRE_GPU=True`). The notebook never reinstalls torch or numpy; it installs only missing packages
(normally `ultralytics==8.4.212` and `lapx==0.13.1`) and records `pip freeze` in the experiment.

## 7. Run

Runtime → Run all. Section 3 prints a line like `EXPERIMENT_ID = 'pie_full_20261116T120000Z'` — note it. Expected order of cost:
Phase 3 (GPU, roughly the video duration or less per clip on a T4) and Phase 4 (CPU, the longest part for long clips) dominate; training is
minutes to hours depending on the number of windows; evaluation and Phases 6–8 are comparatively quick. These are expectations, not measurements.
For a first try, run a separate small experiment with `VIDEO_SUBSET` (e.g. one video per set) and/or `PERCEPTION_MAX_FRAMES`.

## 8. Resume after a disconnect

1. Reconnect (same or new runtime, GPU again), set `EXPERIMENT_ID` to the printed id, keep `WORK_ROOT` unchanged, Run all.
2. Videos whose stage folder on Drive has a valid `_STAGE_COMPLETE.json` for the same configuration are **skipped**; a folder without a valid marker is
   moved to `<experiment>/_quarantine/` (never deleted) and recomputed. Training continues from its newest checkpoint after verifying configuration,
   scaler and dataset hashes.
3. To re-run only one failed stage: run the configuration cell, Sections 1–4 (fast, verification only) including cell **4.4**, then the stage's section.
   Sections 11–13 should be run together.
4. Errors you may see and what they mean: `STALE_ARTIFACT` (an output of a different configuration exists → start a new experiment),
   `LOCKED_CONFIG_CHANGED` (you changed a frozen setting), `CODE_COMMIT_CHANGED` (the code changed since the experiment started; set
   `ALLOW_RESUME_ACROSS_COMMITS=True` only if the change cannot affect outputs — it is recorded).

## 10. Interpreting the results

* **Final status** (end of Section 13) is `COMPLETED` only if every stage completed for every video in scope, all files verify, schemas validate,
  the split is intact, the checkpoint verifies and the tests pass. `INCOMPLETE` or `FAILED` lists what is missing.
* **ADE / FDE** (pixels) use the **most-probable mode** — the model's single forecast. **minADE@K / minFDE@K** let the ground truth pick the best of
  K = 5 modes; they are oracle diagnostics and are always shown separately.
* **Partitions:** `train` numbers are in-sample. `validation` / `test` are separate recordings (no leakage), but they are scored against
  **perceived-track pseudo-targets**, not PIE annotation ground truth. They are *not* independent validation; the Phase 9 gate reports **BLOCKED**
  until an annotated-target adapter with verified identity mapping and frame alignment exists.
* **Conflict indicators** are image-plane quantities (pixels, pixels per second, image-plane time to minimum separation) — not TTC, PET or metres.
* **Risk scores** are uncalibrated heuristics; `calibrated_probability` is `null` and calibration is BLOCKED (no verified conflict labels).
  Categories are provisional engineering thresholds.
* **Alerts** come from the deterministic state machine with engineering thresholds; many close by evidence loss (the pair stops being observed).
  Lead time and false-alarm rates are BLOCKED (no ground-truth events).
* **Timing:** Phase 3 frames per second are offline processing of recorded video; Phases 4–8 are batch replays. Nothing supports a real-time claim
  (the window builder needs future frames, so there is no causal online mode).
* The previous single-video pilot (`set01/video_0004`) results are not part of this experiment.

## 11. Troubleshooting

| Symptom | Fix |
|---|---|
| `git clone … failed` | push the branch, or use `REPO_SOURCE="git_bundle"` |
| weights download fails | download `yolo11n.pt` yourself and place it in `checkpoints/yolo/` |
| `OFFICIAL_SPLIT_UNVERIFIED` | copy `utilities/pie_data.py` from the PIE repository into `data/raw/pie/` |
| `MISSING_REQUIRED_DATA` | a set folder, video or annotation is missing — see the PROBLEM lines of Section 2.2 |
| a video fails in Phase 3 / 4 | its error is printed and stored in the index file; fix and Run all again (only that video is recomputed) |
| `S4A_ROWS` | Task 2 quarantined rows of that video; this Phase 9 contract is kept strict on purpose — inspect `artifacts/…/phase4_task2_kinematics/` in the quarantine folder |
| local disk full | delete `WORK_ROOT/<other experiment>` folders; Section 6 keeps each video's Phase 4 scratch until Section 7.1 has generated its windows, then removes it |
| unexpected test failures in Section 13 | the run is marked FAILED; check `reports/pytest_<session>.log` (numpy 2 / Python 3.12 on Colab were not tested locally) |
